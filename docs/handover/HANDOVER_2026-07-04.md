## SECTION 1 — PROJECT OVERVIEW

**Project purpose.** Sen2Nal is a 6-agent sequential ML pipeline for stock sentiment +
calendar-signal analysis. It combines FinBERT NLP sentiment over news/Reddit with
calendar/seasonal effects to produce transparent trading *signals* (not advice), and runs a
weekly experiment comparing its stock picks against ChatGPT/Gemini/Grok. Educational/portfolio
project; "NOT FINANCIAL ADVICE" is a hard requirement on all outputs.

**Current architecture (as-built, verified).**
- Backend: Python 3.11, FastAPI, SQLAlchemy 2.0 ORM, Alembic, Pydantic v2 settings.
- Pipeline: `src/pipeline/runner.py` runs agents sequentially with halt-on-critical-failure
  gating. Stages 1–5 critical, stage 6 (experiment) non-critical.
  Flow: Ingestion(AG-01) -> Sentiment(AG-02) -> Calendar(AG-03) -> Features(AG-04)
  -> Prediction(AG-05) -> Experiment(AG-06).
- Agents inherit `src/agents/base.py::BaseAgent` (logging, timing, rollback-on-failure,
  optional `_validate_output()` contract hook).
- DB: PostgreSQL star schema (3 dim, 4 fact, 2 staging, 2 pipeline-tracking tables) in
  `src/database/models.py`. Single migration `001_initial_schema.py`.
- API: 4 routers (stocks, experiments, pipeline, alerts) + health/root in `src/api/`.
- Frontend: React 19 + Vite 7 + Tailwind 4 + react-query + framer-motion + recharts.
  Single "NightOps Terminal" dashboard. Defaults to MOCK data
  (`VITE_USE_MOCK_DATA !== 'false'`). Vite proxies `/api` -> `localhost:8000`.
- Scheduler: APScheduler embedded in the API process (disabled by default).
- Data contracts: 5 Pydantic contracts in `src/contracts/` + `src/data_quality/validator.py`.

**Tech stack**: see `pyproject.toml`. Poetry-managed. NOTE: `shap` and `beautifulsoup4`/`lxml`
are commented out in pyproject (MSVC build-tool constraints on Windows).

**Overall engineering objective of this programme.** Two comprehensive studies were completed
BEFORE any code changes:
  1. Architecture Maturity Audit (10 phases) — found the codebase is a strong *prototype*
     with a serious docs-vs-reality gap and specific correctness defects.
  2. Scalability Feasibility Study (10 phases) — concluded expansion to S&P 500 is feasible
     with targeted modification (no rewrite), gated behind fixing signal-validity defects first.
Those produced an **Execution Plan**: 10 epics / 37 modules / 5 waves, ~25–35 engineer-days,
strictly sequenced, one-PR-per-module. This programme is the refactor; universe expansion is
"Horizon 2" and is OUT OF SCOPE until the refactor exit gate passes.

- `docs/adr/ADR-001..005` — 001–004 implemented; **005 (walk-forward) NOT truly implemented**.
- `CLAUDE.md` (project) — governance + architecture; contains ~5 false claims to be corrected

## SECTION 7 — KNOWN ISSUES (pre-existing; NOT current implementation tasks)

These are from the audit/feasibility studies and `docs/KNOWN_ISSUES.md`. They have OWNING
MODULES in the plan; do not fix opportunistically.

Correctness (highest severity):
- **ML label leakage**: `prediction.py` uses same-row `daily_return` as both feature and target
  (`1 if daily_return > 0`); no t+1 shift. Predictions are invalid. -> E2.M1.
- **Fake walk-forward**: ADR-005 claims rolling 252/21-day folds; code just truncates to last
  252 rows and fits once, no test window, no metrics. -> E2.M2.
- **Fake SHAP**: `feature_importance * feature_value` labeled as SHAP; `shap` not installed.
  -> E2.M3 (rename per D2).
- **Vacuous contracts**: only CalendarAgent implements `_validation_records()`; other 4 agents
  silently skip validation despite CLAUDE.md claiming all 5 enforce. -> E3.M3.
- **Missing migration tables**: `pipeline_runs`/`pipeline_logs` absent from migration 001;
  `POST /pipeline/run` would crash on a migrated DB. Tests hide it via `create_all`. -> E1.M1.
- **Prod init.sql password clobber**: `init.sql` (mounted in docker-compose.prod.yml) runs
  `ALTER USER ... PASSWORD 'sen2nal_password'`, overwriting the secure prod password on first
  boot. -> E1.M2 (Docker-blocked; deferred until constraint lifts).
- **Event-loop-blocking pipeline trigger**: `_run_pipeline_background` is `async def` but calls
  the fully sync pipeline -> freezes the API for the whole run. -> E3.M1.
- **Sentiment backlog**: fixed `limit(500)` per run with no drain loop -> unbounded staging
  growth at scale. -> E3.M2.
- **Experiment zero-price bias**: LLMs pick from full S&P 500 but only 10 tickers are priced;
  un-priced picks score 0.0 -> biased comparison. -> E4.M1.
- **`/alerts`**: unbounded history scan + latent NULL 500 on `combined_score`. -> E6.M1.
- **Substring ticker matching** in Reddit ingestion breaks at S&P-500 composition. -> E1.M4/Horizon 2.

Open host/env issues:
- KI-002: Docker daemon not running / OFF-LIMITS by owner.
- KI-010: npm audit — 21 moderate, 7 high (frontend). -> E7.M1.
- gh CLI keyring token invalid (push works via Git Credential Manager; `gh auth refresh` needed).
